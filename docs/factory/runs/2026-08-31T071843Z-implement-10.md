## What changed

One added file, one test — test 25 from `03-design.md` gap 6.

Work is created against the real spawned entrypoint, read back, the process is SIGTERMed, a
second process is started **on the same pinned port**, and the item is gone.

Three structural choices carry the test, because an assert-an-absence test is worthless if it
can pass for the wrong reason:

1. **The port is probed once and pinned across both starts.** "On the same port" is half the
   `done_when`. A per-start probe would let the test pass having proved only that some
   unrelated fresh server elsewhere does not know the item.
2. **The item is read back before the restart, through the same `workitem://{id}` resource the
   final assertion uses.** Without it, a create that never landed or a broken read path would
   satisfy the absence.
3. **The final assertion pins `/unknown work item/`,** not a bare rejection. A missing or
   misregistered resource template rejects with `Resource ... not found` and fails here rather
   than passing as "absent".

`expect(first.exitCode).toBe(0)` rules out the harness's SIGKILL escape hatch masking a
listener that never released the port; the pinned port gets no `EADDRINUSE` retry, so the
second start succeeding is itself the evidence of clean release.
