## Gate 3 amendment 1 — approved 2026-08-30

`docs/factory/specs/FQ-3/03-design-amendment-1.md`. One contract reopened, the
`harness/purview.ts` block. No change to any of the 25 tests, the call flow, dependency
policy, or the three low-confidence decisions.

- `HarnessOptions.withSlack?: boolean` → `HarnessOptions.slack?: SlackFake`. The fake is
  injected, not started inside `startHarness`, and is imported as a type only so slice 0a
  compiles without `slack-fake.ts`.
- `PurviewHarness.slack` becomes `SlackFake | undefined`.
- `tap()` leaves `PurviewHarness` and becomes a free function in a new `harness/tap.ts`.
- `close()` no longer closes the fake. Whoever starts one owns closing it.

The human was offered the alternative that preserves gate 3 exactly — cutting between the
harness modules and the harness consumer, with slice 0a shipping only scaffolding and a
self-test — and chose the decoupled cut, accepting the amendment.

## The constraint that forced `tap()` out, and a defect it exposed

`tap()` needs `signSlackForm`, which lands in slice 0b. Keeping it a method would have made
slice 0b modify `harness/purview.ts`, a file slice 0a creates.

Whether Charter §3's "existing test file" rule covers non-`*.test.ts` helpers under `tests/`
is an open charter question, filed by triage on PR #15 and still unresolved.

Checking it against the approved plan surfaced a defect that had nothing to do with line
counts: **slice 1 was specified as extending `escalation-round-trip.integration.test.ts`**, a
`*.test.ts` file created by another slice. That is caught by §3 under *any* reading, strict or
loose. Slice 1 as approved could not have run unattended, and this was not noticed at gate 4
revision 1.

Resolved by design rather than by waiver: **every FQ-3 slice adds files and never modifies
another slice's.** Slice 1 gets its own file. The charter question remains open and is
recorded as such — the next spec wanting a shared helper will hit it again.
